# This repository is the official implementation of the paper:

"A Driving Preference-Informed Multi-Model Framework for Real-World Electric Vehicle Battery SOH Estimation"
Yifan Chen,  Jiayin Xiao, Song Wang and Yujie Wang.
*IEEE Transactions on Transportation Electrification*, 2026.

## Overview
This repository provides a minimal verifiable package for the proposed framework.
Due to proprietary restrictions on the dataset for all devices, we release a de-identified subset of 4 marginal devices (one per driving preference cluster) for pipeline verification,
together with the raw data of the example device shown in Fig. 3, which allows replotting the capacity-regeneration curve，
so that readers and reviewers can run the released pipeline end-to-end and reproduce the per-device results of the released devices.
Note that the aggregate metrics reported in the paper are computed over the full 300 devices and therefore cannot be reproduced from this subset;
the subset is intended to verify the correctness and self-consistency of the released code, weights, and data.
Additionally, the data of example device exhibited in Fig. 3 is also offered.

The framework:

Clusters devices into 4 driving preference types (Moderate / Normal / Aggressive / Extreme) via GMM on discharging C-rate distribution features.

One sub-model (1 MLP + 2 1D-CNNs) per preference type.

Integrates sub-model outputs with prior weights from GMM posterior probabilities, revised by an MLP gate network.

## Quick Start
From the repository root:

```bash
python test_code.py
```

The script loads the trained framework from 'model/', the features and labels of the selected device from 'data/', runs inference, and saves estimations to 'results/test_output/'.
Set 'device_id' at the top of 'test_code.py' (2–5, corresponding to D02–D05 in the devices list) to choose the device to verify.
The outputs in 'results/test_output/' can be compared with the pre-computed files in 'results/expected_results/' to confirm consistency.
A CUDA GPU is required. Verifying one device takes well under a minute on a modern laptop with a CUDA GPU.

## Data
All processed data is included in this repository (see `data/`).
**Raw device data (D01–D05, ~200MB each) is NOT included.** Download from
[Releases](https://github.com/Shiro-Yi/driving-preference-informed-SOH-estimation/releases/tag/v1.0):
1. Go to the release page, download all 5 CSV files;
2. Create a directory `data/raw/` in the project root;
3. Place the downloaded files there.
The experiment code expects raw data at `data/raw/D01_device_raw_data.csv`, etc.
